# Architecture

appwhy is a SwiftPM package with a core library and a command-line executable.

## Targets

### AppWhyCore

Contains all domain models and diagnostic logic.

Models:

- `AppTarget`: resolved application target
- `Evidence`: observed value with category and source
- `Finding`: deterministic diagnostic result
- `DiagnosticSnapshot`: full collection of evidence and findings for a target
- `VerificationReport`: verification checks and their states

Inspectors:

- `BundleInspector`: reads bundle structure and Info.plist values
- `CodeSigningInspector`: uses Security framework APIs for signature validation and signing details
- `LaunchServicesInspector`: uses `NSWorkspace` to resolve registered paths and detect path mismatches

Engines:

- `VerificationEngine`: maps evidence to verification checks with explicit states
- `ExplanationEngine`: generates high-confidence findings from evidence

The core library is independent of terminal output. It can be reused by other frontends.

### appwhy

Command-line entry point.

Components:

- `CommandParser`: parses subcommands and options
- `InspectCommand`: runs inspection and formats output
- `VerifyCommand`: runs verification and sets exit status
- `ExplainCommand`: runs explanation and formats output
- `OutputFormatter`: generates text and JSON from shared models

### AppWhyCoreTests

Standard SwiftPM test target using XCTest.

Run with:

```bash
swift test
```

This target replaced the previous custom test runner and is the primary test entry point.

## Data flow

1. The CLI parses arguments.
2. `TargetResolver` resolves the target into an `AppTarget`.
3. Each inspector collects evidence and appends it to an array.
4. `DiagnosticSnapshot` holds the complete evidence set and any findings generated by `ExplanationEngine`.
5. For `verify`, `VerificationEngine` evaluates the evidence and produces a `VerificationReport`.
6. `OutputFormatter` renders the same models as text or JSON.

## Design constraints

- No private Apple APIs.
- No third-party dependencies.
- No Xcode project or workspace.
- Missing evidence is represented as absent and never automatically becomes a failure.
- Confidence is explicit on every finding.
